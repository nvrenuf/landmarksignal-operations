# Evidence correction

The earlier report's example PR and printed idempotency key were demonstrations, not proof of a live GitHub return. That report is superseded.

Actual return evidence comes from native root task/run/profile/workspace records and local artifact hashes. The explicit dashboard return publishes this inventory and the actual worker summary to the source issue, then sets Human Review or Blocked. It preserves failure and human-review evidence types and never marks an issue accepted or closed.

The correction suite verifies status mappings, source identity, sprint preservation, approval-record validation, evidence retention, repeat returns, native tool policy, and rollback. Windows installation and a real subsequent worker return must be confirmed from the setup report and GitHub readback. Historical Done cards do not become accepted merely because these files were corrected.
